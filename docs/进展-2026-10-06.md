# 2026-10-06 进展：检索能力落地（内置词法后端）

## 背景

`graph_search / graph_index_status` 自 2026-09-07 起是「骨架 + 确定性降级」：语义链探测
`semantica.vector_store/context/embeddings`，被 venv 里 pinecone 改名桩卡死后恒为
`semantica:false` / `hits:[]`。G-04 的检索面因此对上层（core / 平台 / 样板 / 助手）不可用。

## 本次落地（阶段 2 的离线可交付部分）

- 新增 `graph_engine/adapters/retrieval_builtin.py`：`BuiltinLexicalBackend` 实现既有
  `RetrievalBackend` 契约（`upsert`/`delete` 空实现返回 0——无需索引，`query`/`status` 实做）。
  `query` 由注入的 `RecordsProvider`（`graphId → (entities, relations)`）**现读存储**再打分，
  因此**写后立即生效、无索引维护窗口**，也不需要 pinecone/fastembed/faiss。
- 权重（与 core `graph_search` / `GraphQueryService.search` 同源，改一侧必须同步另一侧与单测）：

  | 命中面 | 权重 |
  | --- | --- |
  | 实体名称精确 / 名称包含或归一 / 别名 / 类型 / docId / 证据文本 | 8 / 5 / 3 / 2 / 1 / 1 |
  | 关系端点名（各端） / 关系类型 / docId / 证据文本 | 3 / 4 / 1 / 1 |

  归一到 `[0,1]`（名称精确命中 = 1.0），同分按稳定 ID 升序（同输入同输出）。
- `adapters/retrieval.py`：`status()` 增 `available`，并合并后端自报 `backend`/`mode`
  （`builtin-lexical` → `mode=lexical`；向量后端 → `mode=vector`）。
- `application/service.py`：新增 `retrieval_backend` 配置（`builtin`（缺省）/ `none`），
  惰性构造时把 `BuiltinLexicalBackend(self._retrieval_records)` 注入适配器；`none` 保留旧降级。
- `config.py`：`GRAPH_ENGINE_RETRIEVAL_BACKEND`；`runtime.py` 透传。
- 测试：新增 `tests/test_retrieval_builtin.py`（10 用例：缺省可用 / 别名·类型·端点名命中 /
  分数单调与确定性 / 空查询与无关词 0 命中 / 写后立即生效 / deprecate 后不召回 / index-status /
  `none` 降级 / normalize / HTTP + MCP 面）；`tests/test_retrieval.py` 的降级用例改为显式
  `retrieval_backend="none"` 并断言 `available is False`。
