# 进展 2026-09-16：core 数据面回写通道（图谱引擎 → ikc-core-service）

## 目标

图谱引擎当前只有本地 SQLite（自带视图），core 的 G-01/G-02/G-03 读面读的是 PG 派生表，两侧不通 →
平台侧看到的图谱永远是空库。本轮补上**引擎 → core 内部写通道**，让「引擎抽、core 落地」的分层闭合。

## 落地

- 新增 `graph_engine/adapters/core_writeback.py`：把**已决策**的实体/关系回写 core
  `POST /internal/graph/build`（契约单一来源：ikc-core-service `docs/API接口与任务契约.md §2.5`，
  实现见 core `domain/services/graph_write_service.py`）。
  - 字段收窄到 core 契约（`_ENTITY_FIELDS` / `_RELATION_FIELDS`）：`type/name/aliases/properties/
    evidence/confidence/canonicalConceptId` 与 `type/sourceEntityId/targetEntityId/properties/
    evidence/confidence`；本地字段（`entityId/graphId/status/时间戳/normalizedName`）不外投
    （core 侧 `extra=forbid`，多余键会被 100001 拒收）。
  - 关系的两端是**实体稳定 ID**（core 不再派生），与 `ikc_sdk.core.graph_ids` 同一契约。
  - 鉴权头 `X-Internal-Token` = core `IKC_CORE_ADMIN_TOKEN`。
  - 开关：未配置 `IKC_CORE_BASE_URL`（或 `IKC_CORE_WRITEBACK=0`）时整体关闭 → 返回 `None`，
    返回体形状与既有行为完全一致；回写失败**不阻断**本地构建（`{"ok": false, "error": ...}` + warning）。
  - 空 `entities/relations` 是合法载荷：语义为「该 doc 本次未再产出资产」，core 只做 doc 级废弃
    （`deprecate_doc` 走此路径）。
  - `ENGINE_VERSION` 优先读 repo `pyproject.toml`（可编辑安装的 dist 元数据滞后）。
- `application/service.py`：`build_from_records`（`build_from_text`/`merge` 复用同一链路）与
  `deprecate_doc` 在启用时追加 `writeback` 字段。
- 分层结论（写入 core 文档 §3.3）：**抽什么在引擎**（NER/LLM 抽取、实体消解、证据挂接、graphSchema），
  **怎么落地在 core**（稳定 ID upsert、别名并集、evidence 去重追加、confidence 取大、计数刷新、
  `graph_build_log`、doc 级废弃、审计）。core 只接受已决策记录、不重做抽取——否则会复活已删除的
  `graph_build_service`，形成第二套实现。

## 验证

- `tests/test_core_writeback.py`（7 例）：字段收窄、开关关闭无副作用、失败不阻断、空记录=仅废弃、
  版本漂移护栏、`http.server` 桩校验端点/鉴权头/载荷。
- `pytest tests -q` → **59 passed**。
- 跨仓实测（ikc-demo 知识库 `kb_e940930947e4478bb08ca1eefed3b6df`，真实 docId）：
  build 返回 `writeback={"ok": true, "added": 4, "nodeCount": 3, "edgeCount": 1}`；
  core G-01 读面 `nodeCount=3 / edgeCount=1`，G-02 `total=3`（names: 接入向导 / 接入指南 / 演示用户）。

## 遗留

- 回写用的 `docId` 必须是 core 已登记的文档（core 读面按来源文档可读性过滤），否则数据面不可见。
- pipeline 编排（core → 引擎的调度）仍未部署；W-03 检索、G-04 邻域/路径同理。

## 追加：文本建图关系抽取（edges>0）与 build 响应记录回传

### 目标

`build_from_text` 的 MVP 规则抽取此前只产实体（文档标题 + 「」/“” 引号候选）、`relations` 恒为空，
落库后 `edges=0`——图谱域演示（core G-01/G-02/G-03、样板 ⑪⑫）不完整。同时 core 已是**唯一写库方**：
core 调 `POST /api/v1/graph/graphs/{id}/build` 后需拿到**已决策记录**再落库，而原响应只有计数。

### 落地

- 新增 `graph_engine/adapters/relations.py`（规则为主 + 守卫式增强）：
  - 切句：`。！？；!?;`、换行、西文 ``". "``；同句内实体**两两共现**成对，按**无序对去重**
    （一对一条边），方向取原文先出现者（同位置按实体 ID 定序，保证确定性）；
  - 只让**能在原文定位**的实体参与（标题等不在正文的实体不产边）；
  - 端点 = `domain.ids.entity_id`（与 `build_from_records` 同一派生规则，core 不再派生）；
  - 类型受 `graphSchema.relationTypes` 约束：优先名称含 `related`/`关联` 的声明类型，其次首个
    声明类型，未声明时 `related_to`；`confidence` = 两端实体置信度取小；
    `properties = {cooccurrence, methods}`；`evidence = [{docId, snippet}]`；
  - `llm=True`（`GRAPH_ENGINE_LLM_ENHANCE`）且 semantica 可用时叠加
    `RelationExtractor(method="cooccurrence")`，与规则结果按同一无序对合并（置信度取大）；依赖缺失/
    构造失败/抽取抛错一律**确定降级**为规则结果（不抛错、不联网）。
- `application/service.py`：`build_from_text` 用该模块填充 `relations`（此前写死 `[]`）；
  `build_from_records` 响应**新增** `entities[]` / `relations[]`（`record.to_dict()`，与 core 回写载荷
  同一批记录），既有 `graphId / entityCount / relationCount / semantica / writeback / deprecated / llm`
  键与语义不变；`merge`/`deprecate-doc` 复用同一链路。
- SDK `BuildResult` 经 `extra` 透传这两个键，本轮不新增 SDK 字段（无消费方需要）。

### 验证

- 新增 `tests/test_relations.py`（10 例）：稳定 ID 端点与证据、schema 类型约束（4 组参数化）、
  单实体/跨句不产边、semantica 增强失败降级、响应记录可被 `EntityRecord.from_dict` /
  `RelationRecord.from_dict` 反向解析且与本地落库一致。
- `pytest tests -q` → **69 passed**（基线 59 + 新增 10）。
- 实测（本机引擎，未配置 `IKC_CORE_BASE_URL`，无回写）：
  `build_from_text`（4 实体文本）→ `entityCount=4 / relationCount=6`，`stat.edgeCount=6`；
  HTTP 面 `POST /api/v1/graph/graphs/{id}/build` → `errCode=0`，`data` 键
  `[entities, entityCount, graphId, relationCount, relations, semantica]`，`GET .../edges` `total=6`；
  证据边 `rel_f5545198c36f`：`ent_7ccd15011fd3 → ent_15c94bebcecb`（`related_to`，snippet 同句）。

### 遗留

- 规则路径只做**类型级** schema 约束，不校验 `sourceTypes`/`targetTypes` 端点类型；长文本的跨句/跨段
  召回留待 LLM 抽取链路评估。
- core 侧新调用方（`POST /api/v1/knowledge-bases/{kb_id}/graph/build`）需按 `data.entities` /
  `data.relations` 落库，不重做抽取。
