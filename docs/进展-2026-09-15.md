## 2. SDK 设计要点（对齐 openwiki-server-sdk 口径）

- **协议解耦**：只依赖 HTTP 契约（`/api/v1/graph/*` + `/health` + `/openapi.json`）与统一响应壳
  `{traceId, errCode, errMsg, data}`；仅第三方依赖 `httpx`，不 import `graph_engine`。
- **双客户端**：同步 `GraphEngineClient` / 异步 `AsyncGraphEngineClient`，共享模型与错误映射；
  `client.graphs.*`（create/list/get/delete/build/merge/deprecate_doc/stat/nodes/edges/neighbors/paths/
  analytics/export/sparql/search/index_status）与 `client.jobs.*`（run/get/list/wait）。
- **traceId**：23 位纯数字（13 位毫秒 + 10 位随机），`X-Trace-Id`/`X-Request-Id` 下发，异常携带便于对账。
- **异常层级**：`GraphEngineError` → `TransportError`（Connection/Timeout/Protocol/HTTPStatus）与
  `APIError`（200001/200404/200409/200500 + 兜底 Business）。
- **重试/超时**：GET 幂等可重试、POST 需显式 `reqId`；`502/503/504` 退避重试，默认 `(connect 5s, read 60s)`。
- **身份语义**：`CallerIdentity`（`X-User-Id`/`X-Tenant-Id`/`X-User-Roles`）透传，并在请求缺省时补齐
  图谱归属参数 `tenantId`/`ownerId`（引擎的租户/归属是请求参数而非请求头）。
- **运行时自检**：`fetch_openapi()`（FastAPI 接口目录）与 `health()`。

## 3. 服务端补齐与修复（SDK 联调驱动）

1. **HTTP 面补齐**（此前仅 MCP/application 层有能力，SDK 无法覆盖）：
   - `GET /api/v1/graph/graphs/{graph_id}/search?query=&topK=` → `semantic_search`
   - `GET /api/v1/graph/graphs/{graph_id}/index-status` → `index_status`
   - 图谱不存在 → `errCode=200404`（HTTP 404）；检索链不可用 → 确定降级（`semantica=false`、`hits=[]`、`reason`）。
2. **`/analytics` 500 修复**：semantica `GraphAnalyzer` 返回结果含 `frozenset`（`communities.communities[]`），
   `JSONResponse` 序列化抛 `TypeError` → 对外 200500。适配层新增 `_jsonable`（`set/frozenset` → 排序 list、
   `tuple` → list、递归 dict/list、`numpy` 标量 `.item()`、其余 `str()` 兜底），并补回归单测。
